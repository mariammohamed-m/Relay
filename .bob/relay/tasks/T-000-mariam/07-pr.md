## Key decisions and rejected alternatives

| Decision | Rationale | Rejected alternative |
|----------|-----------|---------------------|
| Fix `getPurchaseAgeDays()` with `Date.now()` rather than fixing `getRequestNow()` | `getRequestNow()` is intentionally display-only (invoice formatting uses local wall-clock time); changing it silently would break those callsites. Stopping its use in arithmetic is the safer, minimal change. | Fix `getRequestNow()` to use `getUTCHours()` etc. |
| Keep `MANUAL_REVIEW_AGE_DAYS = 90` branch in `validators.ts` even though it is now unreachable (30 < 90) | If `REFUND_WINDOW_DAYS` is ever raised above 90, the manual-review path still activates without a code change. Product has not confirmed the 30-day window is permanent. | Delete the unreachable branch for cleanliness. |
| `auditLog` stored in `db.ts` `Store` | `resetDb()` calls `emptyStore()` which initialises `auditLog: []`; tests call `seedAll()` → `resetDb()` automatically, so audit state never leaks between test runs. | Separate audit log module outside `Store`. |
| `changeBooking` accepts optional `requestedAt` param | Enables deterministic tests without mocking `Date.now()`. Consistent with the project's pattern of not introducing test frameworks. | Mock `Date.now()` with `MockTimers`. |

## Debug notes summary

**gotcha-001** — `getRequestNow()` in [`src/lib/requestContext.ts:7`](hackathon-specific/sample-project/src/lib/requestContext.ts:7) builds ISO timestamps from local `Date` component getters then appends a literal `"Z"`. On non-UTC hosts this is up to ±14 h wrong. Root cause of the original refund-age miscalculation. Fix: `Date.now()` everywhere in arithmetic. **Rule: `getRequestNow()` is display-only.**
